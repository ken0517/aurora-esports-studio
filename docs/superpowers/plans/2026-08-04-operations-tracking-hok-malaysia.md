# Aurora 後台、追蹤與 HOK 馬來西亞實施計畫

## 1. 後台錯誤狀態

- 在後台 UI 測試加入「營運讀取失敗仍顯示錯誤與重試」檢查。
- 修改 `OperationsApp`，明確區分首次載入、錯誤及可用狀態。
- 保留現有訂單／預約／人員元件。

## 2. 客源與轉化追蹤

- 先擴充 acquisition 與 analytics 測試：新渠道、`utm_content`、HOK 頁面與完成報價事件。
- 更新安全欄位白名單及客源摘要。
- 增加集中管理的外部分享網址產生器，避免各處手寫 UTM。

## 3. Google 後台摘要

- 先建立「未設定、成功、上游錯誤」三類伺服器測試。
- 加入管理員專用報表入口與 Google OAuth 服務帳戶簽章；只讀環境變數。
- 後台顯示真實 GA4／Search Console 摘要或可理解的未連接狀態。

## 4. HOK 國家與六大區

- 先測試國家選項及東南亞自動映射。
- 中央配置加入國家資料，但保持正式 `serverRegion` 欄位不變。
- 報價、客服、WhatsApp／LINE、查詢與訂單同步保留國家及六大區。

## 5. 馬來西亞多語言 HOK 頁

- 先增加頁面數量、語言、網址、`hreflang`、內容安全及爬蟲 HTML 測試。
- 在 landing page 資料中加入 `ms-MY`、`en-MY`、`zh-Hans-MY` 三頁。
- 讓共用頁面元件按頁面語言顯示，不改首頁語言系統。
- 同步生成靜態 HTML、結構資料、網站地圖、`llms.txt` 與內部連結。

## 6. 驗證與發布

- 執行全套 Tests、Lint、Build。
- 在本機以桌面及手機尺寸驗證後台錯誤頁、HOK 表單及三個新頁。
- 前端與 Vercel 後端必須同批發布，避免資料欄位不同步。
- 建立 Google Ads 草稿與 UTM 落地頁；最後啟用及付費留待明確確認。

## 7. 磁碟收尾

- 保留仍被 Codex 使用的 C 槽工作檔。
- 不強制刪除已核對但被鎖定的原檔。
- 待使用者醒來後再確認是否刪除 D 槽臨時壓縮包，以免誤刪唯一備份。
