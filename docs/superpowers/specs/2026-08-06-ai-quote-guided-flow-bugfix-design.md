# Aurora 客服自动报价引导修复设计
## 目标

修复顾客询问「传说对决钻石升战场传说」时资料未收齐便被错误显示为人工报价的问题，同时保留现有正式价格、五项服务、Gemini 设置及前端设计。

## 已确认方案

采用服务器端确定性引导：Aurora 客服先从顾客用语中识别游戏、服务、段位简称、小分级及星数，再按中央报价验证结果每次只追问一个缺失项目。资料完整后仍由现有报价引擎计算；只有报价引擎明确返回 `manual_review` 才显示「待人工确认」。

## 行为范围

- 中央段位资料支持可编辑别名；传说对决「战场／戰場」映射至「战场传说／戰場傳說」。
- 升段表达支持「升、升到、上到、到、冲、衝、to」。
- 确定性流程保存多轮回答中的目前小分级、目前星数、目标小分级及目标星数。
- 同一轮只提出一个最重要问题；不会把资料不完整等同人工报价。
- 完整自动报价一律使用服务器正式金额；Gemini 不可改价，也不可把已报价订单说成人工报价。
- 巅峰赛、英雄战力标等原本人工报价项目保持不变。

## 验收例子

「我传说对决钻石想升战场传说，大约多少钱？」应依次收集钻石小分级、目前星数、目标星数，并最终返回现有正式报价。完整资料「钻石 III 0 星到战场传说 0 星」应继续得到原价 HK$675、新人 85 折后 HK$573.75；价格数字本身不在本次修改范围。

## 不在范围内

- 不修改 `pricing.js` 的任何价格。
- 不调整报价表 UI、服务项目、折扣或汇率。
- 不更换 Gemini 模型或 API Key。
