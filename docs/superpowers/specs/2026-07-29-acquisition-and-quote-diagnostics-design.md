# Aurora 客源追蹤與報價診斷設計

## 目標

1. 保留現有中央定價與自動報價邏輯，不改動 HOK 已核准價格。
2. 讓成功自動報價與真正需要人工確認的訊息清楚分開。
3. 在顧客明確同意保存並提交查詢後，記錄 Google、Carousell、Instagram、直接進入或其他客源。
4. 在營運後台顯示客源、報價方式、報價狀態及轉人工原因，並提供只涵蓋已提交查詢的客源統計。

## 已確認根因

完整的 HOK 國際服排位代打、排位陪玩、5V5 陪玩及教學均可自動報價。現時所有 WhatsApp 摘要都以「請客服按以上資料人工確認」結尾，即使狀態已是「報價完成」，容易令顧客誤以為價格未設定。

真正會顯示待人工確認的情況包括：巔峰賽、英雄戰力標、特殊要求、服務未啟用，或找不到完整價格規則。

## 客源資料範圍

只保存：

- 客源分類
- 首次及本次進入頁面（只保存站內路徑）
- 外部來源網站名稱
- 經過清理的 UTM source、medium、campaign
- 首次及最近進入時間

不保存：

- IP 地址
- 裝置指紋
- 完整外部網址
- Google 搜尋字詞
- 廣告點擊識別碼
- 密碼、驗證碼或付款資料

客源只會隨已同意保存的手動報價或 Aurora 客服對話送到後端。

## 後台顯示

- 「報價方式」保留 Aurora 客服／手動報價表。
- 「客源」另外顯示 Google／Carousell／Instagram／直接進入／其他。
- 顯示報價完成、資料未完整或待人工確認。
- 待人工確認時顯示可理解的原因。
- 新增「客源概況」分頁，按日期、遊戲、服務及客源篩選已提交查詢，顯示查詢數、已轉訂單數及轉單率。
- 清楚標示這不是全站瀏覽量；完整曝光、點擊、停留時間及平均排名仍以 Google Analytics 與 Search Console 為準。
